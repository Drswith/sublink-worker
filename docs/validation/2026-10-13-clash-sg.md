# Hysteria2 单节点真实订阅的 Clash/mihomo 可用性结论

验证日期：2026-10-13（北京时间）。

- Rust：`7ae93d83ac54bb2b4ddabb981051ebda21293b2f`。
- Node 对照：`cbabf58f21e231a295badca9e58ddf394f3c8176`。
- 环境：Zeabur 独立验证项目，腾讯云 Singapore 2C/4GB，x86_64；原 Dockerfile 云端构建后的 scratch 应用。
- 客户端：mihomo 1.19.32。

## 结论

**用户提供的两条 Hysteria2 单节点真实订阅，经 Rust 转换后，在 mihomo 1.19.32 中实际验证可用。其他协议仅有合成测试证据，不能据此推断所有真实 Clash 订阅均可用。**

两条地址分别提供普通订阅与 Clash YAML，测试时各包含一个 Hysteria2 节点。Rust 与 Node 的 Clash 输出一致，生成配置能够加载，且两条订阅均完成真实 HTTPS 代理请求。结论限定于当时的输入内容、客户端版本与测试请求路径。

## 真实订阅验证

| 项目 | 结果 |
| --- | --- |
| 原订阅主机抓取 | 两条地址在 SG 均返回 HTTP 200；普通、Clash.Meta、sing-box UA 均成功 |
| 普通订阅 → Clash | mihomo 配置检查通过，客户端 SOCKS HTTPS 请求成功 |
| Clash YAML → Clash | 配置检查通过，HTTP provider 加载一个 Hysteria2 节点，选择该节点后 SOCKS HTTPS 请求成功 |
| 代理出站 | 两次请求均返回有效 Cloudflare HTTPS trace，出口 IP 与 SG 直连不同 |
| Rust/Node 对照 | 实时 Clash 响应一致；同一份上游快照生成的 Clash 响应也逐字节一致 |

“出口不同”指目标网站看到的来源 IP：SG 直连时为 SG 出口，经过订阅节点时为代理节点出口。结合客户端 API 的明确节点选择和有效 HTTPS 响应，证明实际代理传输成功。mihomo 本次默认日志未输出节点名，未把节点名日志作为其通过条件。

测试配置来自 SG 独立 scratch Rust 服务。为在测试容器运行，镜像同一批远程规则文件，并通过 mihomo API 选择节点及 GLOBAL 模式；没有修改节点认证或 TLS 参数。运行不经过本机 Clash Verge，辅助容器没有 HTTP_PROXY / HTTPS_PROXY。

## 合成测试与剩余问题

Clash/mihomo 合成矩阵为 **14/15 通过**。SS、SS2022、VMess TCP/WS+TLS、VLESS WS/REALITY、Trojan、Hysteria2、TUIC、AnyTLS 单协议场景，以及全选项、DNS 关闭、Base64 与 Clash 订阅场景均通过实际传输检查。

唯一失败为**含 `ntp.interval: 30m` 的完整 sing-box 配置 → Clash**，mihomo 因字段类型错误拒绝加载。这是 Node 同样存在的保留行为；用户提供的两条订阅没有触发。只选择 Clash 输出，并不能避免不兼容的完整 sing-box 输入。

其他已知失败涉及 sing-box 1.11 的 AnyTLS 支持、Clash DNS 段转 sing-box、完整 sing-box 的 DNS / `providers` 字段；不影响本次两条真实订阅的 Clash 输出。详情见[已知失败表](../../tests/e2e/README.md#known-failures)。

本报告记录的是 **2026-10-13 SG 独立运行**，使用普通订阅、Clash YAML 两条地址，原主机抓取均成功。日期、环境、输入数量与抓取覆盖不同，SG 成功不否定先前环境失败，也不能由旧仓库记录推导出来。

仓库核对确认：Rust Git 对象和远端分支包含 `7ae93d8`，Node 基线为 `cbabf58`；直连与代理查询结果一致。四类已知失败已记录于固定 Rust 提交的 `docs/rust-rewrite.md:78–80` 与 `tests/e2e/README.md:42–54`。查看其他分支的工作目录不等于查看报告对应版本。

同一订阅快照的 Surge 输出只在 managed-config 自身服务地址头上不同，去掉首行后一致；该差异不影响 Clash 输出。

## Xray 功能边界

固定 Rust 提交的 `src/app.rs:381–415` 与 Node 基线的 `src/app/createApp.jsx:265–313` 中，`/xray` 都执行抓取、文本解码、非空行聚合及 Base64 编码，不调用 Clash YAML 到 Xray 节点的转换逻辑。Rust 的 `try_decode_subscription_lines` 对本次 YAML 保留整段文本，因此输出仍是编码后的 YAML。

这是现有接口的功能边界，不是 Rust 重构新增退化。没有实施功能修复；Xray 文本 round-trip 不证明真实 Xray 客户端可用。本报告的使用结论继续限定于 Clash/mihomo。
